Chapter 3 · 第 3 章

git 时光机：给代码装上存档点

c83f5a1 · ch3main

前两章你一定经历过：AI 改了三版，最好用的是第一版，可惜回不去了。这一章给项目装上存档点——每次满意就存一次，随时读档，改崩了不慌。

⏱ 约 45 分钟 · 前置：第 2 章

01为什么需要存档

三个每天都在发生的场景：

🖱️ AI 连改五轮，越改越糟，你想回到「第二轮那个能跑的版本」——没有存档，回不去。
🔍 隔了一周，你（或 AI）问「这个数字的口径当时怎么改的来着」——没有历史，查不到。
🙌 同事说「把你做的分析给我看看最新版」——你发过去的是哪一版？你自己都不确定。

类比时刻：游戏存档

打游戏的人都知道：进 Boss 房前先存档，打输了读档重来，好装备拿到手马上再存一次。git 给你的项目提供一模一样的东西——commit（提交）= 存档，存档说明 = commit message，存档列表 = git log。你已经用过一次 git clone 了（第 0 章拿教材），今天正式开开这台时光机。

好消息：你在第 0 章克隆的课程文件夹本身就是一个 git 仓库（里面藏着 .git 文件夹，就是它干的），我们直接在里面练。

02第一次存档

先办一张「身份证」（只需一次）

每个存档都要署名（是谁存的），所以先告诉 git 你是谁。终端里执行（名字邮箱随意，但以后别改来改去）：

终端 · 一次性配置（引号用英文的！）
git config --global user.name "王小明"
git config --global user.email "xiaoming@example.com"

存第一个档

在项目里新建一个文件 学习笔记.md（记事本右键新建、或直接让 AI 建都行），随便写两行，比如「今天学会了让 AI 分析表格」。然后在项目根目录（vibe-coding-academy 文件夹）的终端里，按「查看 → 装车 → 存档 → 查看」四步走：

终端 · 在 vibe-coding-academy 目录下
# ① 看看现在什么情况：红色 = 有改动还没存档
git status
Untracked files:
  学习笔记.md        ← 红色，git 还不认识它
# ② 装车：把改动放进待存档清单（理解为「加入购物车」）
git add 学习笔记.md
# ③ 存档！-m 后面是存档说明，说清楚「这次干了什么」
git commit -m "添加第一篇学习笔记"
[main a1b2c3d] 添加第一篇学习笔记
 1 file changed, 2 insertions(+)
# ④ 查看存档列表：一行一个存档点，最新的在最上面
git log --oneline
a1b2c3d 添加第一篇学习笔记        ← 你刚才存的
f0e9d8c 课程官方的最后一次更新      ← clone 时自带的

每页顶部那条橙色圆点导航，画的就是这张存档列表——一个点一个存档，HEAD 指着「你现在站在哪个存档上」。

03存档说明怎么写

存档说明（commit message）是写给三个人看的：未来的你、你的同事、还有 AI。半年后翻 log，它就是你的工作日志。

❌ 坏说明✅ 好说明
修改按月份汇总加入 2024 报告
改了点东西修复日期为文本导致月度统计漏行的问题
update销售员排行前三名加高亮样式

口诀：一个动词开头，说清做了什么。一行足够，别写作文。

04看改了什么 & 后悔药

现在改一下 学习笔记.md（加一行字），感受时光机的两个日常动作：

终端 · diff 看差异 / restore 吃后悔药
# 改动还没存档时，先看看「到底改了哪几行」
git diff 学习笔记.md
+ 今天发现数据是脏的，习惯就好      ← 绿色加号：新增的行
# 满意 → 老三样存档
git add 学习笔记.md && git commit -m "笔记：记录数据清洗心得"
# 后悔 → 一键撤销还没存档的改动，回到上次存档的样子
git restore 学习笔记.md
进阶：穿越回某个旧存档看看（选学）
终端 · 观光模式
# 哈希取 log 里前几位即可（比如 a1b2c3d）
git checkout a1b2c3d
You are in 'detached HEAD' state.
（意思是：你脱离了最新进度，处于「观光」状态，看看就好）
# 看完回到现在：
git switch main

要带回某个文件的历史版本也有办法（git checkout 哈希 -- 文件名），但日常 90% 的场景用 restore 就够了——先把基础三板斧（status / add+commit / log）练熟。

从这章起，给自己立个新规矩：每当 AI 做出了让你满意的东西，马上存一个档。AI 负责写代码，你负责在正确的时刻按下存档键——这就是 vibe coding 的安全带。

05课后三件套

动手做：三个存档点

对 学习笔记.md 完成三次独立的存档：① 新建并写下今天学到的两件事；② 修改其中一行；③ 再追加一段「踩坑记录」。每次存档前先 git status 看红色，存档后 git log --oneline 确认多了一条。

点开看参考过程
终端 · 参考过程
git status
modified: 学习笔记.md   ← 红色，说明有未存档的改动
git add 学习笔记.md && git commit -m "笔记：补充 git 存档用法"
[main 9f8e7d6] 笔记：补充 git 存档用法
git log --oneline
9f8e7d6 笔记：补充 git 存档用法
a1b2c3d 添加第一篇学习笔记
f0e9d8c 课程官方的最后一次更新

连做三轮，直到「status 看红 → add → commit → log 看新纪录」变成肌肉记忆。这个循环你以后每天要转几十次。

自测 3 题（点击展开答案）

1. add 和 commit 有什么区别？

add 是「把改动放进购物车」（暂存），commit 是「结账打包成一个存档」（提交）。可以多次 add 不同文件后一次 commit——相当于凑齐一单再结账，存档说明只写这一单的事。

2. git status 显示红色，代表什么？

有改动还没存档：红色文件名 = git 看到了变化（新文件或被修改），但还没进存档。每次动手前后各看一眼 status，是你对项目的「仪表盘」。

3. 为什么存档说明不能每次都写「修改」？

存档列表是你和团队的工作日志，也是回滚时的「地图」——想回到「加高亮之前」，靠的就是说明里那句「销售员排行前三名加高亮样式」。全写「修改」，时光机就成了没有路牌的高速公路。

翻车急救箱

① commit 时报错：Please tell me who you are
忘了办「身份证」。执行本章开头的两条 git config 命令，然后重新 commit。

② fatal: not a git repository
终端不在项目文件夹里。敲 cd 走到 vibe-coding-academy 目录再试（提示符里能看到当前路径）。

③ 刚 commit 完发现说明写错了 / 少 add 了一个文件
说明写错：git commit --amend -m "新说明" 改最近一次存档；漏了文件：先 add，再 git commit --amend --no-edit 补进去。

④ 命令敲了没反应或报一堆引号错误
九成是中文引号/中文冒号混进命令了。终端里的引号必须是英文的（"），说明文字里可以用中文。

⑤ 想撤销还没存档的改动，restore 报错
确认文件名拼写和路径（在项目根目录执行）。注意 restore 是「回到上次存档」，没存过档的新文件它管不了，直接删掉文件即可。
