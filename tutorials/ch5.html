Chapter 5 · 第 5 章

协作剧场：一个人演完团队协作

8e4f2b7 · ch5main

真实团队最怕的事：两个人同时改同一个文件，把对方的活儿覆盖掉。这一章你分饰 Alice 和 Bob 两个角色，亲手制造一次真实的合并冲突——再亲手解决它。演完这出戏，你就懂了全世界程序员天天在干什么。

⏱ 约 60 分钟 · 前置：第 4 章 · 需要一个免费 GitHub 账号（现注册即可）

01分支：合同草稿与原件

先解决一个概念：什么是分支（branch）。

你改一份重要合同，不会直接在原件上涂改——原件随时要能用。你会复印一份当草稿，改到满意再把定稿替换回原件。git 分支就是这件事：main 是原件（随时能跑、随时能给人看的版本），分支是草稿（试验新功能，改砸了原件毫发无伤）。改好了，把草稿合并（merge）回原件。

类比时刻：剧场与分身

真实的团队里，Alice 和 Bob 是两台电脑上的两个人：Alice 开个分支做新功能，Bob 同时在 main 上修小问题，两人互不打扰，最后把成果合到一起。今天你一个人分饰两角——用两个文件夹扮演两台电脑，把整场戏自己演一遍。演技不重要，重要的是走位：每一步都问自己「我现在是谁、在哪个文件夹、在哪条分支」。

那两人怎么「交换代码」？靠一台云端的仓库。这就请出本章第二位主角。

02给项目安个云盘：GitHub

GitHub 是全世界最大的代码云盘（微软家的，免费），干两件事：备份（电脑坏了代码还在）和中转（多台电脑、多个人的仓库在这里会师）。

用浏览器打开 github.com，注册一个免费账号（用户名以后会出现在你的仓库地址里，起个顺眼的）。然后点右上角 + → New repository：名字填 vibe-coding-academy，选 Private（你的私有仓库），然后什么都不要再勾——不要 README、不要 .gitignore，我们本地全有——点 Create repository。

现在把本地仓库的「收件地址」改成你自己的仓库，并把全部存档推上云：

终端 · 在 vibe-coding-academy 目录下
# 你克隆课程时 origin 指向课程官方仓库（只能拉、不能推），换成你自己的：
git remote set-url origin https://github.com/你的用户名/vibe-coding-academy.git
# 首次推送。-u 的意思是「记住这条线，以后 push/pull 不用再写全名」
git push -u origin main
Enumerating objects: …
Writing objects: 100%
（第一次 push 会弹出浏览器让你登录 GitHub，点 Authorize 授权即可，之后电脑会记住）

刷新 GitHub 页面——你的仓库里躺着从第 3 章到现在的全部存档。这台「云盘」从此就是团队的会师地点。

03开场：两个文件夹，两位演员

现在搭建剧场：从你的云端仓库克隆出两份，当作 Alice 和 Bob 的两台电脑。原来的 vibe-coding-academy 文件夹功成身退（内容已在云端），接下来的戏都在新文件夹里演：

终端 · 回到 vibe-coding-academy 的上一级目录
# 退到上一级目录（放课程文件夹的地方）
cd ..
# 从云端克隆两份，分别命名为 alice 和 bob——两台「员工电脑」
git clone https://github.com/你的用户名/vibe-coding-academy.git alice
git clone https://github.com/你的用户名/vibe-coding-academy.git bob
Cloning into 'alice'… done.
Cloning into 'bob'… done.

化妆间规则只有一条：换角色先换文件夹（cd alice / cd bob），进了化妆间再看一眼提示符，确认自己「是谁」。

04第一幕 · Alice：开分支做新功能

需求来了：给看板加一个「城市 Top 10」榜。Alice 不动 main，先开草稿分支：

终端 · Alice（cd alice 进入）
# 开一条新分支并站上去：switch 是「切换」，-c 是「新建」
git switch -c feature/city-top10
Switched to a new branch 'feature/city-top10'
# 分支名习惯用 feature/功能名，一眼看出这条草稿是干什么的

然后干第 4 章课后练习同款的事——在 alice 的 example 目录启动 AI（cd example 再 claude），说：

在看板里加一个「销售额 Top 10 城市」条形图，随筛选器联动；同时把页面标题改成「📊 2024 年销售看板（城市榜版）」。改完自己确认能跑。

已添加城市 Top 10 图并更新标题，自测通过，请刷新看板验收。

验收满意，Alice 存档（在 alice 目录、仍在 feature 分支上）：

终端 · Alice（先 /exit 退出 AI，回到 alice 根目录）
git add example/dashboard.py
git commit -m "新增城市 Top 10 榜，标题标注城市榜版"
[feature/city-top10 3d7a1c9] 新增城市 Top 10 榜，标题标注城市榜版

注意：这个存档只存在于草稿分支上，main 此刻还不知道它。Alice 不着急合并——她打算歇口气。而在这段时间里，Bob 动手了。

05第二幕 · Bob：在 main 上改标题

另一边，老板觉得看板标题不够正式，让 Bob 把标题改成「📊 2024 年度销售看板」。Bob 不需要新功能，直接在 main 上改这一行小字：

终端 · Bob（新开一个终端窗口：cd bob）
# 用记事本打开看板文件，找到第一处 st.title 那行，照下面改：
notepad example\dashboard.py
改这一行（只动引号里的字）：
  旧：st.title("📊 2024 年销售看板")
  新：st.title("📊 2024 年度销售看板")
改完保存关闭（Ctrl+S）
git add example/dashboard.py && git commit -m "标题改为 2024 年度销售看板"
git push
Writing objects: 100%
（Bob 的改动已上云。此刻云端 main 的标题，和 Alice 草稿里的标题，已经不是同一句话了——雷已埋下）

Bob 全程不知道 Alice 在干什么——这正是并行工作的常态。冲突不是谁的错，是并行的代价。

06第三幕 · 会师：merge 撞出冲突

Alice 休假归来，决定把城市榜合并进 main。职业习惯：合并前先拉取云端最新进度（不然她根本不知道 Bob 改过东西）：

终端 · Alice（回到 alice 根目录）
# ① 回到 main（原件）
git switch main
# ② 拉取云端最新进度——把 Bob 的标题改动拿下来
git pull
Updating 8e4f2b7..a1c93d5
 1 file changed（Bob 的改动到手，本地 main 已与云端同步）
# ③ 合并自己的草稿分支
git merge feature/city-top10
CONFLICT (content): Merge conflict in example/dashboard.py
Automatic merge failed; fix conflicts and then commit the result.

冲突发生了，恭喜！原因一眼看穿：Alice 和 Bob 都改了同一行标题，git 不知道该听谁的——它不敢替你做主，把决定权连同现场一起交给你。用记事本打开文件，冲突现场长这样：

example/dashboard.py · 冲突现场（notepad example\dashboard.py）
<<<<<<< HEAD
st.title("📊 2024 年度销售看板")        ← 你所在的 main（Bob 的版本）
=======
st.title("📊 2024 年销售看板（城市榜版）")  ← 被合并的分支（Alice 的版本）
>>>>>>> feature/city-top10

三条分隔线把文件劈成两半：HEAD 这边是你所在分支的版本，>>>>>>> 那边是合并进来的版本。解决冲突 = 你来当裁判，改成最终该有的样子——两边的心意其实可以都要：

手动改完后的这一行（把三行现场改成一行，删除所有 < = > 标记）
st.title("📊 2024 年度销售看板（城市榜版）")

保存关闭，然后照常存档收尾——对 git 来说，解决冲突就是「一次普通的修改 + 提交」：

终端 · Alice
git add example/dashboard.py
git commit -m "合并城市榜：标题采用年度+城市榜版"
[main 5f8d201] 合并城市榜：标题采用年度+城市榜版
# 推上云，剧场谢幕；用完的草稿分支顺手拆台
git push
git branch -d feature/city-top10

冲突不是事故，是制度

注意 git 的立场：它绝不等冲突发生才提醒你，也绝不擅自动你一个字。两个版本打架时，它把现场保护起来，停下来等裁判。世界上每天发生上亿次合并，绝大多数不冲突；冲突的那些，最终都由一个「懂业务的人」按了裁决键——今天那个人是你。

07团队三约定

把这出戏浓缩成三条团队铁律（真实团队全都这么干）：

约定做法防什么
开工先 pull每天动代码前，先 git pull 拉最新在旧版本上干半天活，合并时处处冲突
干完就 push存档（commit）完随手 git push电脑罢工丢进度；同事拿不到你的成果
新功能开分支正经改动一律 git switch -c feature/xxx，小步提交main 随时被改坏；改动太大冲突难解

三条合起来就是一句话：main 永远可用，草稿随时可弃，云端永远最新。

08课后三件套

动手做：二轮演出「页脚之争」

这出戏的续集，冲突点换到看板页脚。剧情：Bob 开分支 feature/footer，在看板末尾加一行 st.caption("数据截至 2024-12-31")（记事本或 AI 都行）；同一时间 Alice 在 main 上给看板末尾加了 st.caption("本看板由 AI 协助生成") 并 push。然后 Bob 回 main 拉取、合并——冲突会在「看板末尾相邻的位置」爆发，把两句都留下来，完成合并。

点开看参考走位
终端 · 摘要（谁、在哪个文件夹、敲什么）
# Bob（bob 文件夹，先拉最新——铁律第一条）：
git pull
git switch -c feature/footer
在 example/dashboard.py 末尾加一行 st.caption("数据截至 2024-12-31")，然后：
git add example/dashboard.py && git commit -m "页脚注明数据截止日期"
# Alice（alice 文件夹）：
git pull
在 example/dashboard.py 末尾加一行 st.caption("本看板由 AI 协助生成")，然后：
git add example/dashboard.py && git commit -m "页脚署名 AI 协助" && git push
# Bob 合并：
git switch main && git pull
git merge feature/footer
CONFLICT (content): Merge conflict in example/dashboard.py
记事本打开，两行 caption 都保留（删干净 < = > 标记），然后：
git add example/dashboard.py && git commit -m "合并页脚：截止日期+AI署名" && git push

演完用 git log --oneline --graph 看一眼——你的提交历史里出现了真正的「分叉再汇合」。

自测 3 题（点击展开答案）

1. 分支和 main 的关系，用合同的话怎么说？

main 是原件（随时可用、对外展示的正式版），分支是复印件草稿（随便涂改、随时丢弃）。草稿定稿后 merge 回原件。新功能开分支，保证 main 永远处于「能跑」的状态。

2. 冲突现场里 <<<<<<< HEAD 和 >>>>>>> 两段各是什么？解决冲突本质上是在做什么？

HEAD 段是你当前所在分支（main）的版本，>>>>>>> 段是被合并进来的分支版本。解决冲突 = 把这段现场改写成「最终该有的样子」（常是两边意图的合并），删掉所有标记行，然后 add + commit。git 只负责保护现场，裁决永远是人。

3. 为什么 Alice 合并前要先 git pull？

并行协作时你不知道别人推了什么。先 pull 把云端最新拿到本地，冲突在本地暴露、本地解决；不 pull 就合并，你的 main 还停在旧进度，push 时照样会被云端拒绝——问题不会消失，只会换个地方炸。开工先 pull，是团队第一条铁律。

翻车急救箱

① push 报 rejected / non-fast-forward
云端有你没有的存档（别人先推了，或你在别处推过）。按铁律办：git pull 拉下来（有冲突就按第三幕解决）再 git push。

② 冲突现场看不懂、越改越乱，想反悔
可以整场撤销：git merge --abort 回到合并之前的样子，喘口气再来。草稿分支还在，什么都没丢。

③ push 弹出登录窗口失败 / 反复要求密码
Windows 上首次 push 会弹浏览器的 GitHub 授权页，跟着点 Authorize 即可。没弹窗却报 403：多半登录的是另一个账号，去「Windows 凭据管理器」删掉 github.com 的旧凭据再试。

④ clone 报 repository not found
三个嫌疑：仓库地址拼错；仓库是 Private 而这台「电脑」没登录；你登错账号。逐个对——尤其 alice/bob 两边登录的要同一个账号（这出戏你一人分饰两角，不是真的两个账号）。

⑤ 建仓库时手滑勾了 README，push 报错
云端多了一个你本地没有的存档。最省事：把云端仓库删了（Settings → Delete）按本章重来，这次什么都不勾。
